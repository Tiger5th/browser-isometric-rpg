# Spec: P1 垂直切片——单区域完整玩法闭环

Status: ready-for-agent
前置：specs/p0-prototype-validation.md（已完成，artifacts/p0-final-report.md）
词汇表：GLOSSARY.md　相关 ADR：0001–0005

## Problem Statement

P0 已验证全部技术假设并产出了灰盒 Harness，但项目还没有「游戏」——没有任何可玩的内容。P1 的目标是用量最小的正式内容，把点击移动→战斗→对话→任务→存读档的完整玩法闭环跑通，同时把 P0 的验证性代码转化为可长期生长的游戏骨架。

## Solution

一个单区域的垂直切片：二次元风格主角（VRoid 或占位角色）在一个手工布局的区域内探索、战斗、接任务、对话、存读档。游戏逻辑全部数据驱动（EntityId + 修饰器 + ink 对话 + 任务 JSON），内容与引擎代码分离，为 P2 的 Agent 批量内容生产铺路。

## User Stories

1. 作为玩家，我想点击地面让角色走过去，以便用经典等距 RPG 方式探索
2. 作为玩家，我想角色走到敌人附近时敌人察觉并攻击我，以便体验战斗威胁
3. 作为玩家，我想点击敌人发起攻击，以便主动战斗
4. 作为玩家，我想战斗胜利获得经验和掉落物，以便有成长反馈
5. 作为玩家，我想角色死亡后从最近存档点复活，以便失败不会毁掉进度
6. 作为玩家，我想走近 NPC 时出现对话提示，以便知道可以交互
7. 作为玩家，我想点击 NPC 开始对话并用选项推进，以便体验叙事
8. 作为玩家，我想对话选项能触发任务，以便从叙事进入玩法
9. 作为玩家，我想接任务后看到目标提示与进度，以便知道要做什么
10. 作为玩家，我想完成任务获得奖励（装备/物品/属性），以便任务有回报
11. 作为玩家，我想打开背包查看/使用/装备物品，以便管理收获
12. 作为玩家，我想穿装备后属性即时变化（修饰器生效），以便成长可感知
13. 作为玩家，我想随时手动存档，以便掌控进度
14. 作为玩家，我想关掉浏览器重开后从存档恢复，以便进度真正持久
15. 作为玩家，我想旧版本存档在新版本游戏里自动迁移，以便长期游玩不被抛弃
16. 作为玩家，我想看到 HP/经验/任务状态的 HUD，以便掌握状态
17. 作为玩家，我想角色被建筑遮挡时描边显示，以便不迷路
18. 作为玩家，我想动画/画面是二次元卡通风格（toon 渲染），以便有目标审美
19. 作为开发者，我想所有内容（敌人/NPC/任务/对话）都是数据文件，以便 Agent 能批量生产内容
20. 作为开发者，我想 GameSession 可在无渲染环境驱动，以便 L1 全覆盖玩法规则
21. 作为开发者，我想 ego-browser 能驱动页面玩完整闭环，以便 L4 冒烟可自动验收
22. 作为开发者，我想性能预算持续被断言，以便内容增长不悄悄毁掉帧率
23. 作为项目所有者，我想人工玩一遍完整闭环并验收，以便确认「好玩」的底子存在

## Implementation Decisions

- **单一 seam：GameSession**（新，在 src/logic）：持有 Entity 集合、任务状态、对话状态、战斗判定、游戏时钟；暴露 `snapshot()`（可序列化）与 intent 接口（moveTo/attack/talk/useItem/equip/save）——渲染层只消费快照 + 提交意图。P0 的 Harness 保留为验证工具，不与 GameSession 混合。
- **战斗**：回合制起步——攻击 = 意图 → 命中/伤害公式（用修饰器后属性）→ 事件流。敌人 AI 状态机（idle→patrol→chase→attack→dead）在 GameSession 内，移动层接 Crowd V2。
- **对话**：复用 P0 验证的 inkjs 封装；任务触发 = 对话标签 → GameSession 事件。
- **任务**：数据驱动任务表（接取条件/目标/奖励），奖励 = 修饰器/物品发放；修饰器 schema 已在 P0 冻结（`(base + Σadd) × (1 + Σmultiply)`，该形状来自 P0 原型）。
- **存档**：GameSession.snapshot() → IndexedDB（P0 的迁移链雏形已就位）；读档 = 快照恢复 + 渲染层重建。
- **渲染**：复用 P0 的角色工厂/正交相机/加载门/toon 材质；输入 = 射线拾取 + Crowd V2 移动；遮挡描边复用 P0 场景方案（零分配射线-OBB）。
- **动态分辨率/画质档位：P1 必须项**（P0 实测 300 角色无余量）。
- **内容最小集**（全部 content/ 目录数据文件）：1 区域、1 主角、2 NPC（1 个对话+任务）、3 敌人（同模板变体）、1 任务（杀 3 敌→奖励→回报）、4 物品（1 装备 + 1 消耗品 + 2 杂项）。
- **预算**：按 07 修正后预算执行（帧率分辨率联动判定）。
- **P0 遗留并入 P1**：VRoid 真人资产（用户手做 15 分钟）、Blender 安装、toon shader morph 支持。

## Testing Decisions

- 好的测试只测外部行为：给定 GameSession 状态 + 意图 → 断言快照变化（战斗/任务/存档全如此，不 mock 内部）。
- L1（vitest）：GameSession 纯逻辑驱动（时间步进手动推进），战斗/任务/对话/存档/修饰器全规则覆盖。
- L2：content/ 数据过 schema + 引用完整性（任务引用的敌人/NPC/物品必须存在）。
- L4（ego-browser）：完整闭环冒烟——存档→移动→战斗→对话→任务→存档→刷新→读档，断言 HUD 与状态。
- L5：预算断言（fps/draw calls/内存），夜间不阻塞。
- 先例：复用 P0 的 perf.ts 监控与报告格式。

## Out of Scope

多区域/流式；背包/装备 UI 全量（最小可用即可）；音效音乐；技能树/成就；多语言；移动端适配；多人。

## Further Notes

- 验收标准：人工玩一遍完整闭环不崩且预算达标。
- **content/ 数据格式的稳定性优先级高于功能丰富度**——它是 P2 Agent 批量内容生产的合同。
- 玩法细节（战斗风格等）以最小假设先行，数据驱动使推翻重调成本低。
