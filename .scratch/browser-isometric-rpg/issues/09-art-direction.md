## Answer（研究结果，2026-10-17）

### 已确认事实

**AI 3D 生成工具对比**

| 工具 | 价格 | 商用许可 | 关键能力 |
|---|---|---|---|
| **Meshy** | 免费（100 积分/月）→ Pro $20/月（1000 积分≈100 资产） | 免费档：CC BY 4.0（署名可商用）；**Pro 起私有许可** | 官方一致性工作流文档；600+ 动作库；Blender/Unity 等 DCC Bridge；API/MCP（Agent 可驱动） |
| **Tripo** | 免费（200 积分≈13 模型，**非商用**）→ Pro $20/月（3000 积分≈200 模型） | 免费档明确禁商用；Pro 起商用 | Retopology（重拓扑）内建、8K 纹理、Native Quad Mesh（对后续手工/管线处理友好）、Smart Segmentation |
| **Hunyuan3D-2**（腾讯，开源本地部署） | 免费自部署 | **自定义社区许可**：EU/UK/韩国不可用；月活 >100 万需向腾讯申请许可 | 15.1k stars；本地部署可控、无按件成本；有 Blender 插件 |
| **TRELLIS**（微软，开源本地部署） | 免费自部署 | **代码 MIT**；模型权重另行声明需逐个核对 | 14k stars |

**一致性机制（Meshy 官方文档确认的方法）**
- Meshy **不跨生成保持角色身份**——一致性 = 每次生成喂相同视觉锚点：同一参考图（三视角 turnaround：正面/45°/侧面）+ 固定措辞的描述（"cobalt blue armor, not royal blue"级别）+ **复用首代资产的贴图**（albedo/roughness/normal 手动重贴）。
- 官方建议流程：先出满意的 A-pose/T-pose 基础模型 → 后续姿势用 custom pose 重摆，**不重新生成**。
- 官方明确：**风格化（stylized）> 写实**——风格化微细节少、面部漂移显著降低；写实面部一致性基本要靠后期手工修。
- 官方承认做不到像素级一致，预期轻度手工清理。

### 一致性技术方案（本票核心交付，结合管线）

```
[风格锚定层]
  风格参考板（一批固定风格关键词 + 3–5 张官方风格图）→ 所有生成共用
[生成层]
  首代 A-pose 模型 → 定稿为「canonical 资产」
  后续资产：图生 3D（以 canonical 渲染图 + 参考板为输入）
[统一化层]（05 号管线新增 AI 资产适配段）
  1. Tripo/Meshy 生成 → 重拓扑（Tripo 内建 retopo 或 Blender 手动）
  2. 贴图统一：canonical 资产贴图复用为主 + 统一调色 LUT 校正
  3. 引擎侧风格化后处理（Babylon：统一光照/描边/色彩分级）拉齐残差
[校验层]
  05 lint 规则按 AI 输出加固：非流形检查、三角数阈值（AI 常超标）、贴图尺寸归一
```

**要点**：一致性是**管线属性**（锚定 + 复用 + 统一化 + 校验），不是单靠生成工具——这正好契合「AI 生成 + 你自己动手」的决策，大部分工作发生在 Blender/管线侧，不锁定任何生成工具。

### 明确推荐

1. **主工具：Meshy Pro（$20/月）**——商用私有许可 + 动作库（省动画量巨大）+ API/MCP 可被 Agent 驱动。Tripo 作为二选（retopo 更强）；两者都按月订阅、可随时切换，无锁定。
2. **风格方向：风格化（stylized low-poly 或手绘感）**——AI 一致性最友好 + 等距 RPG 主流审美（Divinity/Hades 系）+ 贴图/三角预算最省。
3. **开源本地部署（Hunyuan3D）不作为主线**——许可地域限制 + 自部署维护成本，保持为「大批量生产期的降本选项」记录在案。

### P1 首批资产清单（垂直切片最小集）

- 1 个主角（canonical A-pose + 走/跑/攻击/待机 4 动作，Meshy 动作库起步）
- 2–3 个敌人变体（同风格、同一 canonical 流程）
- 1 个小区域场景集：地面模块 ×3、墙/建筑模块 ×5、植被 ×3、道具 ×5
- UI 骨架（不用 AI，直接画/代码）

## 补充决策与修订（2026-10-17，用户更新需求）

**用户新输入**：风格方向 = **二次元（原神系）**；目的 = **自己玩，不商用**。

### 修订研究：免费 + 二次元风格的方案

**关键事实**

- **VRoid Studio**（Pixiv，免费，Win/Mac/iPad）：二次元人形角色定制器，预设部件 + 参数化捏人 + 直接绘制贴图，**产出的模型可免费用于任何用途**（官网明确）。输出 VRM 格式（glTF 2.0 扩展，开放规范）。
- **VRM 格式**：glTF 扩展（vrm-c/vrm-spec，开放规范）；Babylon 有社区 loader（babylon-vrm-loader，MIT）但**已停更（2024-03 最后提交）**——稳妥路径是 VRM→glTF 转换（Blender VRM 插件导出 glTF，或在线转换工具），进 05 号标准管线，绕开停更 loader。
- **动画**：VRoid 角色是标准人形骨架 → **Mixamo**（Adobe，免费）自动绑骨 + 动作库重定向（Blender 烘焙后进管线）；VRM 生态另有 VRMA 动画格式。
- **场景/环境物件**：VRoid 只管人形角色。环境需要另解——AI 生成（Meshy 免费档 CC BY 署名即可，不商用无压力）或免费二次元风格资产包（Booth 上的 VRM 配套场景件等，需逐个看授权）。
- **Hunyuan3D 免费档可用性提升**：不商用 + 自部署 = 无 MAU 烦恼（那 100 万月活条款与个人项目无关），可作为场景物件的免费生成补充。

### 修订推荐（免费 + 二次元 + 自用）

| 资产类型 | 方案 | 成本 |
|---|---|---|
| 主角/NPC 人形角色 | **VRoid Studio 捏人**（二次元正中靶心，参数化保证角色间风格一致） | 免费 |
| 角色动画 | **Mixamo 重定向**（自动绑骨 + 动作库） | 免费 |
| 场景/环境/道具 | **AI 生成**（Meshy 免费档 / Tripo 免费档 / 本地 Hunyuan3D，风格锚定靠贴图统一 + Babylon 卡通渲染后处理） | 免费 |
| 观感拉齐 | Babylon 侧 **toon shading / 自定义描边 + 统一色彩分级**（引擎侧渲染风格是二次元观感的最大杠杆，比资产侧更有效） | 免费 |
| VRM → 管线 | Blender VRM 插件导入 → 按 05 规范导出 glTF → 标准管线 | 免费 |

**一致性方案修订**：二次元风格下一致性杠杆重新排序——
1. **引擎侧卡通渲染（最大杠杆）**：统一 toon shader + 描边 + 色彩分级，能掩盖资产间大量差异
2. VRoid 参数化保证人形角色互相一致（同一模板出身）
3. 贴图统一调色（原方案保留）

### 结论

**全部免费可行**：VRoid（角色）+ Mixamo（动画）+ AI 免费档（场景件）+ Babylon toon 渲染（拉齐）。此前「Meshy Pro + 风格化」推荐作废，替换为本方案。商用许可风险清零（VRoid 模型自由使用、AI 免费档署名即可、不商用）。

**待实测**（并入 P1 前置）：VRoid 角色 → Blender → glTF → Babylon toon 渲染的完整走通；Mixamo 动作在 Babylon 骨骼动画系统中的重定向质量。

## Comments

### 2026-10-17 · 17 号票实测反馈（降级路线 A）

- **环境阻塞**：本机无 Blender / VRoid Studio，Mixamo 无 Adobe 登录态。真实 VRoid→Mixamo→glTF 链路未走通，已用程序化二次元占位角色验证渲染侧；用户 15 分钟手做指引见 17 号票 Comments。
- **Babylon toon 材质现状**：9.31.0 的 `@babylonjs/core` / `@babylonjs/materials` 均未导出 `ToonMaterial` / `PBRToonMaterial`（旧版 `Materials/toon` 路径已移除）。自实现 ShaderMaterial（三阶色阶 + rim light + 顶点色×贴图）可行，且能通过 Babylon 的 `bonesDeclaration`/`bonesVertex` include 支持蒙皮；描边用 `Mesh.renderOutline` 可用，色彩分级用 `DefaultRenderingPipeline`。建议 09 的「引擎侧卡通渲染是最大杠杆」继续成立，但技术选型改为 **自定义 ShaderMaterial / NodeMaterial**，不要假设官方 ToonMaterial 可用。
- **坐标系坑**：glTF 右手系 → Babylon 默认左手系，loader 翻转 Z；相机朝向必须按加载后的实际朝向校准（本次首次截图拍到了角色背面）。
- **morph 坑**：VRM blendshape/表情会作为 glTF morph target 导入；自定义 toon ShaderMaterial 默认不应用 morph，真实 VRoid 表情需要 NodeMaterial、StandardMaterial 或给 shader 增加 morph include。P1 若要做表情/眨眼，需提前排期。
- **骨骼重定向**：VRM `J_Bip_*` 与 Mixamo `mixamorig:*` 命名差异大，Mixamo 动作必须经 Blender 重定向/烘焙；建议 P1 把「Mixamo → VRoid 骨架」固化为 Blender 脚本，而不是运行时按名字匹配。
- **描边**：`renderOutline` 适合单层蒙皮角色；VRoid 的多层头发/面部网格可能叠加描边，P1 建议评估 13 号票的屏幕空间/后处理描边。
- **建议**：二次元渲染链路可继续投入；真实资产获取作为用户手做前置项排期（VRoid + Blender + Adobe 账号），不阻塞引擎侧 toon/描边开发。

### 2026-10-17 · 二次修订：Gemini 生图 + 贴图混合方案（用户确认）

用户反馈：灰盒景色效果差，希望用 Gemini 生图 + 贴图路线。五项决策（全部按推荐）：

1. **范围 = 混合方案**：环境/建筑/植被/道具全面贴图化（贴图贴低模几何/贴花）；角色保持 3D（占位角色顶 P1 主角）。
2. **生成器 = Gemini 生图为主**（ego-browser 登录驱动）；图生 3D（Meshy/Tripo 免费档）选项保留不关闭。
3. **占位角色继续当 P1 主角**；票 25 验收改为「占位 3D 角色 + 贴图环境」组合观感；真实角色路线（序列帧/图生 3D）环境贴图见效后再定。
4. **作废/暂缓**：VRoid/Mixamo 手做项作废；Blender 暂缓不装（角色路线定后再议）。
5. **流程 = 风格锚定先行**：先出 3–5 张锚定参考图供用户挑选，定稿后批量生成环境贴图集，避免风格漂移返工。
