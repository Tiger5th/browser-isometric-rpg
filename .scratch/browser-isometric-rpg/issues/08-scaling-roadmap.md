### 内容扩展策略

- **章节 = 数据包**：一个章节 = 内容 JSON（对话 ink + 任务 + 实体表）+ 区域文件（glTF + 元数据）。引擎代码不随章节增长——增长的是数据，由 Agent 按 06 约定批量生产，L2 校验把关。
- **地区 = 区域文件的组合**：多地区只是更多区域文件 + Floating Origin 保证坐标不炸。架构上单章节与多地区无差别。
- 可维护性关键：EntityId+修饰器模型稳定后不再改 schema（改要走存档迁移链 + ADR）。

### 阶段路线图（每阶段有可验证完成标准）

**P0 原型验证（决策技术假设）**
- 内容：最小可玩切片（灰盒）。验证清单 = 01–07 的「待原型验证」汇总：
  1. 300 骨骼动画角色同屏帧率（WebGL2 vs WebGPU）
  2. Crowd V2 navmesh 200×200 生成时间/内存 + 跨区域热替换
  3. HighlightLayer 多角色遮挡开销
  4. AssetContainer 50MB 区域加载耗时
  5. Editor 项目 git 友好度（不过关 → LDtk 降级）
  6. meshopt vs draco、自动 LOD 质量、KTX2 Safari 兼容
  7. inkjs 长对话树 + 变量存档快照
  8. 修饰器模型三场景表达力
  9. ego-browser headless 冒烟测试稳定性
- 完成标准：每项有实测数字，07 预算修正，ADR 补充。

**P1 垂直切片（第一章第一个区域）**
- 内容：一套完整玩法闭环（点击移动→战斗→对话→任务→存读档）+ 正式资产管线跑通（Blender 源文件→lint→运行时）+ 测试五层全上线。
- 完成标准：ego-browser 冒烟全绿；预算达标；人工能玩完整闭环。

**P2 完整第一章**
- 内容：3–5 区域、10+ 任务、完整对话树、敌人行为状态机、装备/背包全量 UI。
- 完成标准：内部可完整通关；存档跨版本兼容演练通过。

**P3 扩展期（多地区）**
- 引入行为树替换状态机、无缝流式加载（升级 03 的触发方式）、内容 Agent 批量生产管线化。
- 完成标准：新区域生产周期（数据包→上线）≤ 约定值。

### 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| Babylon 发版快，API 变动 | 中 | 锁版本 + 季度评估（已决策） |
| Babylon Editor 社区维护停滞 | 中 | 双轨数据层，LDtk 降级路径（已备） |
| headless WebGL 冒烟不稳定 | 中 | ego-browser 优先；L4 允许重试，L5 不阻塞 |
| 内容生产量超预期（美术是长尾） | 高 | 数据驱动 + Agent 批量生产；美术资产是 P2 起的主要瓶颈，提前启动风格定版 |
| 修饰器模型 schema 变更引发存档不兼容 | 高 | P0 原型充分验证后才冻结 schema；迁移链从第一天就有 |
| 性能预算不达标（移动端尤甚） | 中 | P0 第 1、4 项最早验证，不达标先砍画质目标再砍平台 |

### 成本估算基础

- 开发主力 = AI Agent + 人工决策/验收（本项目模式）。代码成本低；**成本大头是内容与美术资产生产**（P2 起主导）与原型迭代轮次。精确估算待 P0 结束（届时生产速率有实测数据）。

### 进入 /to-spec 的建议

**建议 P0 原型验证完成后进入 /to-spec**，理由：P0 的 9 项验证直接决定规范里的技术参数（预算数字、LOD 策略、编辑器路线终选）。但可以**先做一件事**：P0 之前，用 /to-spec 规格化「P0 原型验证任务本身」（9 个验证项各成一个 spec），让原型阶段就有任务拆分与验收标准。
