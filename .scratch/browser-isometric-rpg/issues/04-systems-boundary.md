## 问题

六大 RPG 系统各自的边界、数据模型与成熟可复用方案是什么？哪些自研、哪些采用现成库/中间格式（如 Ink / Yarn 对话）？

## 调研范围

- 对话：Ink、Yarn Spinner 等在 JS/TS 生态的运行时现状。
- 存档：序列化与版本迁移策略（存档兼容性是长期扩展的硬需求）。
- 任务/背包/装备：是否存在可信的开源参考实现，还是全自研？评估时区分「demo 级代码」与「生产级」。
- 各系统间接口的最小公共数据模型草案。

## 产出

- 自研 vs 复用决策表 + 理由
- 系统接口草案

## Answer（研究结果，2026-10-17，引擎 = Babylon.js）

### 已确认事实

**对话**
- **Ink**（inkle，MIT，5k stars）：业界最成熟的叙事脚本语言（80 Days、Disco Elysium 等使用）。JS 运行时 `inkjs`（y-lohse/inkjs，MIT，658 stars，2026-09 仍维护）。工作流：inkle 的编辑器写 ink → 编译成 JSON → 运行时执行。
- **Yarn Spinner**（MIT，2.9k stars，活跃）：Unity 生态为主，Web/JS 生态弱于 Ink。
- 结论倾向：**对话采用 Ink**（语言成熟 + JS 运行时可用）。风险：inkjs 是个人维护的移植（非 inkle 官方一等），复杂用例需原型验证。对话内容数据格式独立于引擎，绑定风险低。

**存档**
- 存储：IndexedDB（浏览器大数据存储），封装库 `idb`（jakearchibald，ISC，7.4k stars，活跃）。
- 序列化与版本迁移是**自研核心**：存档兼容性是长期运营硬需求。方案草案：存档 = 版本号 + 数据分节（世界状态/实体状态/系统状态），每版本一个迁移函数链（v1→v2→v3 逐级升级），存档写入前先迁移到最新版本。用 JSON（或 CBOR 减体积）。**此子系统自研，无可信现成方案**。

**任务 / 背包 / 装备**
- 调研到的开源参考（RPG-JS 1.7k stars 等）均为**框架级 demo**，其任务/背包实现是示例质量，不是可复用的生产组件——「开源直接采用」路线不成立。
- 结论：**任务/背包/装备自研**，但按数据驱动设计（内容 = JSON/脚本数据，系统 = 通用逻辑），与 03 的关卡数据格式、06 的 Agent 生产方式衔接。

**敌人 AI**
- 移动层：Crowd Navigation V2（02 已定）。
- 行为决策层：行为树（BT）是 RPG 敌人 AI 的行业标准形态。JS 生态无统治级行为树库（多数为小型 demo 级）——**行为树自研**（核心逻辑约几百行，可控），或先用简单状态机、行为树在内容扩展期引入。

### 自研 vs 复用决策表

| 系统 | 决策 | 理由 |
|---|---|---|
| 对话 | **复用 Ink（inkjs 运行时）** | 语言成熟、工具好、数据格式无绑定 |
| 存档 | **自研**（IndexedDB + idb + 版本迁移链） | 兼容性是长期命脉，无现成生产方案 |
| 任务 | **自研**（数据驱动） | demo 代码不可用；数据驱动让 Agent 可生产内容 |
| 背包/装备 | **自研**（数据驱动） | 同上 |
| 敌人 AI 移动 | **复用 Crowd V2** | 已定于 02 |
| 敌人 AI 行为 | **自研**（状态机起步 → 行为树） | 无成熟库；核心逻辑量小 |

### 系统间最小公共数据模型（草案）

```
EntityId（全局唯一）
├─ 身份: type, templateId, displayName
├─ 状态: position, rotation, stateTag[]
├─ 容器: inventory[]（item 实例 + 数量 + 附魔槽）
├─ 属性: attributes{...}（装备加成=修饰器列表）
└─ 引用: dialogueId?, questIds?, aiProfileId?
```
- 任务/背包/装备/存档/对话全部围绕 EntityId + 修饰器（modifier）模型运作；装备加成、任务奖励、buff 共用同一修饰器机制。
- 所有系统状态可序列化 = 存档能力的自然结果（数据驱动设计的附带收益）。

### 待原型验证的假设

1. inkjs 处理中长对话树（几百节点）的性能与存档快照（variablesState 序列化）能力。
2. 修饰器模型在装备/任务/buff 三场景下的表达力（原型一个用例）。
3. 存档迁移链在实际改 schema 时的维护成本（模拟两次迁移）。

### 需要人工决策

- 对话采用 Ink——确认？（备选：自研极简对话 DSL，代价是放弃成熟工具链）

## 决策（2026-10-17，用户确认）

- **对话采用 Ink**（inkjs 运行时）。
- 存档/任务/背包/装备/行为 AI 自研，数据驱动 + EntityId + 修饰器公共模型。
